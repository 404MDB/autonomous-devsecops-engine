# Phase 8: AI Security Intelligence Layer

## Objective

The objective of this phase is to implement an AI Security Intelligence Layer inside the DevSecOps pipeline.

This layer analyzes security evidence generated by previous pipeline stages and produces a risk-based security summary, remediation guidance, and release decision.

The AI Security Intelligence Layer helps convert raw security scan outputs into meaningful security insights that can support secure release decisions.

## Step 3: Implement AI Security Intelligence Parser

A Python-based parser was created:

```text
ai-security-engine/src/security_intelligence.py
```

The parser performs the following tasks:

| Input | Analysis Performed |
|---|---|
| Trivy JSON | Counts vulnerabilities by severity, identifies top CVEs, checks fixed versions |
| OWASP ZAP XML | Counts DAST alerts by risk level and extracts top alerts |
| CycloneDX SBOM | Counts software components and component types |
| Cosign Verification TXT | Confirms whether image artifact signature verification passed |
| Combined Evidence | Calculates risk score and release decision |

---

## Step 4: AI Risk Scoring Logic

The AI Security Intelligence Layer uses weighted severity scoring.

| Finding Type | Weight |
|---|---:|
| Trivy CRITICAL | 10 |
| Trivy HIGH | 7 |
| Trivy MEDIUM | 4 |
| Trivy LOW | 1 |
| ZAP HIGH | 7 |
| ZAP MEDIUM | 4 |
| ZAP LOW | 1 |
| Missing / Failed Cosign Verification | 25 |

Risk levels are calculated as follows:

| Risk Score | Risk Level |
|---|---|
| 100 or above | CRITICAL |
| 60 to 99 | HIGH |
| 25 to 59 | MEDIUM |
| Below 25 | LOW |

---

## Step 5: Release Decision Logic

The AI layer generates one of the following release decisions:

| Decision | Meaning |
|---|---|
| BLOCK_RELEASE | Release must be stopped due to critical risk |
| MANUAL_REVIEW_REQUIRED | Release requires security review |
| APPROVE_WITH_MONITORING | Release can continue with monitoring |

Current decision rule:

```text
If CRITICAL vulnerabilities exist, block the release.
If Cosign verification fails, block the release.
If HIGH findings exist, require manual review.
Otherwise, approve with monitoring.
```

## Step 10: Jenkins Pipeline Automation

The AI Security Intelligence Layer was integrated into the Jenkins pipeline.

New Jenkins stage:

```groovy
stage('AI Security Intelligence Analysis') {
    steps {
        echo 'Running AI Security Intelligence analysis...'

        sh '''
            set -e

            mkdir -p ai-security-engine/input
            mkdir -p ai-security-engine/output
            mkdir -p reports/ai

            rm -f ai-security-engine/input/* || true
            rm -f ai-security-engine/output/* || true
            rm -f reports/ai/* || true

            cp reports/trivy/trivy-image-report.json ai-security-engine/input/trivy-image-report.json
            cp reports/zap/zap-report.xml ai-security-engine/input/zap-report.xml
            cp reports/sbom/dummy-upi-app-cyclonedx.json ai-security-engine/input/dummy-upi-app-cyclonedx.json
            cp reports/cosign/dummy-upi-app-signature-verification.txt ai-security-engine/input/cosign-verification.txt

            docker run --rm \
              -v jenkins_home:/var/jenkins_home \
              -w "$WORKSPACE" \
              python:3.12-slim \
              python ai-security-engine/src/security_intelligence.py

            cp ai-security-engine/output/ai-security-summary.json reports/ai/ai-security-summary.json
            cp ai-security-engine/output/ai-security-report.md reports/ai/ai-security-report.md
            cp ai-security-engine/output/release-decision.txt reports/ai/release-decision.txt

            echo "===== AI RELEASE DECISION ====="
            cat reports/ai/release-decision.txt

            test -s reports/ai/ai-security-summary.json
            test -s reports/ai/ai-security-report.md
            test -s reports/ai/release-decision.txt

            echo "AI Security Intelligence analysis completed successfully."
        '''
    }
}
```

The stage was placed after DefectDojo uploads and before the final Trivy CRITICAL gate.

Pipeline order:

```text
Upload Trivy Report to DefectDojo
↓
Upload ZAP Report to DefectDojo
↓
AI Security Intelligence Analysis
↓
SCA: Trivy Container Scan Critical Gate
```
